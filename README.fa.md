# SETAYESH OS — نسخهٔ ۱٫۱

برای تغییرات، مرز پوشش و دستور ارتقا از ۱٫۰ ابتدا `RELEASE-1.1.fa.md` را بخوانید. طرح معماری مقصد در `ARCHITECTURE.fa.md` است. بخش «پوشش واقعی» در انتهای این سند خط پایهٔ نسخه ۱٫۰ را توضیح می‌دهد.

PWA فارسی تک‌کاربره برای برنامه هفتگی، دفتر مطالعه و پروژه، گزارش‌های محلی و اعلان اختیاری سیستم‌عامل اندروید. فایل `PLAN.fa.md` تحلیل ظرفیت زمانی و معماری است. بسته هیچ دفتر نمونه، نام مشتری یا کلید خصوصی ندارد.

## اجرا روی رایانه (بدون اعلان)

۱. فایل ZIP را استخراج کنید. Node.js نسخهٔ ۲۴ یا بالاتر لازم است.
۲. ترمینال را در پوشهٔ `setayesh-os` باز کنید:

```sh
node server.js
```

۳. `http://localhost:8080` را در Chrome باز کنید. برای هستهٔ محلی نیازی به `npm ci` یا حساب کاربری نیست. یک بار صفحه را آنلاین یا با سرور محلی در دسترس باز کنید تا Service Worker فایل‌ها را ذخیره کند. در تنظیمات پس از ثبت اولین داده، خروجی JSON بگیرید. قالب باید به شکل وب سرور اجرا شود؛ بازکردن مستقیم `index.html` با `file://` کافی نیست.

## انتشار HTTPS و نصب روی Android

- یک میزبان Node با فرایند ماندگار و HTTPS لازم است. فرایند Node باید اجرا بماند؛ هاست‌های خواب‌رونده یا اجرای فقط زمان درخواست برای یادآور مناسب نیستند. کل برنامه و API باید در ریشهٔ یک origin باشند، نه در زیردایرکتوری. داده‌های `localhost` و دامنهٔ نهایی جدا هستند؛ با JSON انتقال دهید.
- نمونهٔ VPS: دامنه را به IP سرور وصل کنید، پورت‌های ۸۰/۴۴۳ را باز کنید و پشت پراکسی HTTPS اجرا کنید. Node به‌صورت پیش‌فرض فقط روی `127.0.0.1:8080` گوش می‌دهد. در Caddyfile:

```caddy
os.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

- سرویس Node را زیر یک حساب محدود و با راه‌اندازی مجدد خودکار اجرا کنید. نمونه systemd (مسیر Node و پوشه را جایگزین کنید؛ برای اعلان، پوشهٔ `private` باید قابل نوشتن فقط برای حساب سرویس باشد):

```ini
[Unit]
Description=SETAYESH OS
After=network-online.target
[Service]
User=setayesh
WorkingDirectory=/srv/setayesh-os
ExecStart=/usr/bin/node --env-file-if-exists=.env server.js
Restart=on-failure
UMask=0077
NoNewPrivileges=true
[Install]
WantedBy=multi-user.target
```

- در Chrome اندروید آدرس HTTPS را باز کنید، از منو «نصب برنامه» یا «افزودن به صفحه اصلی» (بسته به نسخه Chrome) را انتخاب کنید. `http://192.168…` معمولاً محیط امن محسوب نمی‌شود. انتشار روی دامنه یا ساخت APK در این بسته انجام نشده است. برای ارتقای فایل‌های رابط، نام `CACHE` در `public/sw.js` را عوض کنید تا نسخه قدیمی کنار گذاشته شود؛ داده‌های IndexedDB با این کار حذف نمی‌شوند.

## فعال‌سازی Web Push

در پوشهٔ پروژه:

```sh
npm ci
npm run keys --silent
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

مقادیر را با کپی `.env.example` به `.env` وارد کنید. `VAPID_SUBJECT` یک نشانی تماس برای سرویس Push، مانند `mailto:admin@your-domain.example` است و بهتر است نشانی مدیر واقعی باشد. روی Linux/macOS دسترسی فایل را محدود کنید (`chmod 600 .env`)، آن را به مخزن کد نفرستید و کلیدها را به اشتراک نگذارید. سرور را با `npm start` راه‌اندازی کنید. برای اعلان فقط **یک نمونه Node و یک دستگاه** را در نظر بگیرید. SQLite در `private/push.sqlite` است؛ در محیط کانتینر حجم دائمی را با `DB_PATH` مشخص کنید.

۱. روی گوشی و دامنهٔ HTTPS: تنظیمات ← اعلان اندروید. کلید خصوصی `PUSH_SETUP_KEY` را وارد کنید؛ با بازخوانی صفحه دوباره لازم است.
۲. منطقه زمانی را بررسی کنید (برای ایران `Asia/Tehran`)، ساعت و روزها را مشخص کنید و دکمهٔ ثبت دستگاه را بزنید. مجوز اعلان را در Chrome و در تنظیمات اندروید تأیید کنید. زمان‌بندی پیش‌فرض: ۰۵:۰۰، ۲۰:۰۰ و ۲۰:۳۰.
۳. یادآور یک‌باره‌ای برای ۳ دقیقهٔ بعد بسازید، برنامه و برگه مرورگر را ببندید (Chrome را Force Stop نکنید)، سپس اعلان و دکمه «۱۰ دقیقه بعد» را روی گوشی بررسی کنید. تاریخچه در تنظیمات با ورود مجدد یا بازکردن پیکربندی تازه می‌شود.
۴. اگر اعلان نیامد، ابتدا تاریخچهٔ سرور، ساعت محلی، مجوزهای Android/Chrome، شبکه گوشی و دسترسی خروجی سرور به سرویس Push را بررسی کنید. `پذیرفته‌شده` فقط یعنی سرویس Push درخواست را پذیرفته، نه اینکه Android آن را نشان داده است. Focus، مدیریت باتری، Force Stop، شبکه و محدودیت مرورگر بر تحویل اثر دارند. اعلان جای زنگ بیدارباش قابل‌اتکا را نمی‌گیرد. روزانه‌ها و یک‌باره‌ها حدود ۱۰ دقیقه مهلت پردازش دارند؛ سرور توقف طولانی را جبران نمی‌کند. در خطای شبکه تلاش خودکار مجدد انجام نمی‌شود؛ وضعیت ناموفق ثبت می‌شود. حذف دستگاه از تنظیمات، صف و تاریخچه سرور را پاک می‌کند؛ ارسال‌هایی که قبلاً پذیرفته شده‌اند ممکن است دیگر قابل پس‌گرفتن نباشند. دکمهٔ تعویق در مرورگرهای پشتیبان و با اتصال به سرور کار می‌کند؛ هر اعلان یک بار قابل تعویق است.

### مرز داده‌ها

- IndexedDB و JSON شامل نام و شماره مشتری و یادداشت‌ها هستند **و در سطح برنامه رمزنگاری نشده‌اند**. از قفل دستگاه و محل امن برای فایل پشتیبان استفاده کنید. پشتیبان، اعلان‌ها را شامل نمی‌شود؛ بازیابی جایگزین کل دفتر جاری می‌شود و ادغام نمی‌کند. حذف دادهٔ مرورگر می‌تواند دفتر را از بین ببرد. پایداری به مرورگر و Origin بستگی دارد.
- هیچ دفتر شخصی بدون انتخاب کاربر به سرویس بیرونی ارسال نمی‌شود. اتصال Push فقط با کلید و ثبت دستگاه انجام می‌شود؛ سرویس مرورگر اطلاعات اشتراک و پیام عمومی رمزنگاری‌شده را دریافت می‌کند. نام، عنوان خصوصی یا شماره تماس به Push فرستاده نمی‌شود. یک‌باره‌ها مستقل از دفتر محلی‌اند؛ پس از حذف، انجام یا انتقال کار، یادآور قدیمی را دستی لغو کنید.
- هدف مطالعه و قالب تکرارشونده هر بار از تنظیمات فعلی محاسبه می‌شوند. تغییر قالب می‌تواند نمای بلوک‌های پیشنهادی گذشته را تغییر دهد، اما جلسه‌های ثبت‌شده، گزارش‌ها و رکوردهای روزهای قبل پاک نمی‌شوند. درصد تست بر پایه همه تست‌ها (شامل نزده) است و نمره منفی اختیاری است. تمرین مفید فیلم را دوباره به‌عنوان جلسه مطالعه وارد نکنید.

## پوشش واقعی و موارد باقیمانده

- **فعال:** داشبورد، برنامه هفتگی و پیشنهاد انتقال با تأیید، مطالعه و تست/خطا، مباحث، مرور، مدرسه، توقف و تمرین فیلم، سفارش‌های اسپیگات و تقویم فهرستی جداگانه دو پروژه، دفتر انگلیسی و آزمون کوتاه واژگان/دستور، کارگاه‌های مقدماتی مهارت، خواب و ورزش و تغذیه بدون کالری‌شماری، مراقبت شخصی و ثبت دستی استفاده از گوشی، بازنگری و گزارش روز/هفته/ماه، آفلاین، CRUD، JSON، سرویس زمان‌بندی اختیاری Web Push.
- **مقدماتی یا انجام نشده:** دستیار قاعده‌محور است نه مدل زبانی و بازچینی همه کارهای فردا را خودکار نمی‌کند؛ پیشنهاد انتقال تک‌بلوک است. دفتر مدرسه ثبت مستقل و دستی است، نه برنامه رسمی درس/ساعت خودکار. طرح هفتگی بلوک‌های پایه دارد ولی زمان وعده‌ها/تفریح/مسیر رفت انعطاف‌پذیر است و با کارهای شخصی کامل می‌شود. فهرست و تاریخ مرور دستی است و الگوریتم فاصله‌گذاری کامل وجود ندارد. آزمون زبان استاندارد نیست، ماژول‌ها دوره جامع، فایل صوتی/ویدئویی یا ضبط درون‌اپ ندارند. تقویم شبکه‌ای و تاریخ‌گزین کاملاً شمسی، پیگیری خودکار زمان گوشی، تحلیل عمیق همه شاخص‌های ماهانه، اعلان شخصی با متن اختصاصی، همگام‌سازی خودکار ابری و APK بومی در این نسخه نیستند. تاریخ در صفحه شمسی نمایش داده می‌شود؛ ورودی تاریخ استاندارد سیستم ممکن است میلادی باشد.

## اعتبارسنجی

`npm ci` و سپس `npm test` آزمون‌های قواعد برنامه، آمار، تولید درخواست رمزنگاری‌شده Web Push و صف سرور با تحویل شبیه‌سازی‌شده را اجرا می‌کند. `test/browser_smoke.py` تست اختیاری Chromium با CDP است: درگاه‌های ۹۲۲۲ (Chrome) و ۸۰۸۰ (برنامه)، و ماژول‌های `requests` و `websocket-client` لازم‌اند. آن را **فقط روی پروفایل آزمایشی تازه** اجرا کنید: دادهٔ origin محلی را پاک می‌کند. آزمون مرورگر همهٔ فرم‌ها و اعلان گوشی فیزیکی را پوشش نمی‌دهد؛ برای انتشار، سناریوی تحویل HTTPS روی دستگاه واقعی را اجرا کنید.
